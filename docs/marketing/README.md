## Governing truth

All present-tense product claims must remain consistent with:

- [`../business/DECISION-2026-08-31-TWO-PRODUCT-PILOT.md`](../business/DECISION-2026-08-31-TWO-PRODUCT-PILOT.md);
- [`../product/MODULE_LEDGER.md`](../product/MODULE_LEDGER.md), including its cross-product section;
- [`../product/FALSIFICATION_TESTS.md`](../product/FALSIFICATION_TESTS.md);
- the release and deployment class actually used for the demonstration;
- current test and review evidence.

When these disagree, the narrower verified claim wins. Marketing copy does not change product status.

## First decision session

The first cross-functional session should approve only five things:

1. the category problem and product line;
2. the exact release represented by the public experience;
3. the flagship paper title and accountable author;
4. owners for the architecture, three-path scenario, approval lab, and evidence lab;
5. one Tier-1 community contribution and its technical owner.

Implementation estimates, channel dates, and paid promotion follow only after those dependencies have
owners and the narrative/product gates are understood.
